# GameWIP Implementation Checklist

## Purpose

This file tracks implementation work that exists, is partially complete, or still needs to be added.

It answers:

> “Has this feature or system been implemented in code?”

This file is not the proof checklist.

* Use `testing_checklist.txt` for validation requirements.
* Use `roadmap.txt` for planned development order.
* Use `decisions.txt` for stable project decisions and standards.
* Use `platform_backend_contract.txt` for detailed backend boundary rules.

---

## Status Legend

```text
[ ] Not implemented
[-] In progress
[x] Implemented
[~] Implemented but needs cleanup/refactor
[!] Blocked or waiting on a decision
```

# 15. How to Extend This File

When adding implementation work:

1. Add the item under the closest existing system section.
2. Use `[ ]` for work that has not been implemented.
3. Use `[-]` for work actively in progress.
4. Use `[~]` for code that exists but needs cleanup or refactor.
5. Use `[x]` only when the code exists in the project.
6. Do not mark something done only because it is planned.
7. Do not add proof requirements here; put them in `testing_checklist.txt`.
8. Do not add long-term architecture explanations here; put them in `decisions.txt`.
9. Do not duplicate the full roadmap here.
10. Add new major sections only when implementation work for that area has started.

A good implementation checklist item says what code exists.

A bad implementation checklist item only says what the project eventually wants.
