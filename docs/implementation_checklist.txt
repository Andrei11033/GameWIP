Implementation checklist
========================

Purpose
-------
This file tracks implementation work that exists or still needs to be added. It is not the proof checklist; use `testing_checklist.txt` for validation requirements.

Platform backend convention
---------------------------
[x] `cmake/GameWIPPlatform.cmake` resolves `GAMEWIP_PLATFORM_ID`.
[x] Tool libraries load backend sources from `platform/${GAMEWIP_PLATFORM_ID}/*.cpp`.
[x] Tool libraries optionally include `platform/${GAMEWIP_PLATFORM_ID}/platform.cmake` for platform-specific links, resources, and generated files.
[x] Current Windows backend id is `win32`.

Logger library
--------------
[x] Logger builds as a separate library target.
[x] Public API supports normal async logs and synchronous reports.
[x] Normal logs are async, queue-based, and filterable.
[x] `Logger::report(...)` writes synchronously and bypasses filters/queue.
[x] Report timeout overloads write first, then perform a bounded drain.
[x] Queue drops are separated from diagnostics such as format/file/allocation failures.
[x] Unknown SourceId values are accepted and counted.
[x] Logger-owned fatal popup path exists through report/fatal-terminate APIs.
[x] Logger internal test hooks exist under `tools/logger/internal/logger_test_hooks.h`.
[x] Logger hook-forced failure tests cover rare file/popup/timeout branches.
[x] Logger core delegates OS behavior through `tools/logger/internal/logger_platform.h`.
[x] Logger package config polish exists for `find_package(GameWIP_Logger CONFIG REQUIRED)`.

Assert library
--------------
[x] Assert builds as a separate library target.
[x] ASSERT / VERIFY / UNREACHABLE report fatal failures through Logger.
[x] CHECK / CHECK_ONCE / ENSURE report recoverable errors through Logger.
[x] ASSERT_INTERACTIVE / VERIFY_INTERACTIVE exist as separate developer workflows.
[x] Interactive actions support Break, Abort, Ignore Once, and Always Ignore.
[x] Common Controls v6 manifest support is provided for the Windows TaskDialog path.
[x] Automated interactive tests can use `GAMEWIP_ASSERT_TEST_ACTION`.
[x] Manual UI tests can open real Windows dialogs when enabled.
[x] Assert internal test hooks exist under `tools/debug/assert/internal/assert_test_hooks.h`.
[x] Assert hook-forced tests cover action-dialog fallback, fallback-dialog failure, debugger overrides, and popup suppression overrides.
[x] Assert core delegates OS behavior through `tools/debug/assert/internal/assert_platform.h`.
[x] Assert package config polish exists for `find_package(GameWIP_Assert CONFIG REQUIRED)`.

TestSupport library
---------------
[x] `tools/test_support` contains the library target files, public header, core implementation, and platform implementation.
[x] TestSupport builds as a static library target named `TestSupport`.
[x] TestSupport exposes alias target `GameWIP::TestSupport`.
[x] TestSupport public API lives in `tools/test_support/test_support.h`.
[x] TestSupport public API lives under namespace `GameWIP::TestSupport` with no global namespace pollution.
[x] TestSupport implementation uses `core/test_support.cpp` for platform-neutral behavior.
[x] TestSupport Windows child-process backend uses `platform/win32/win32_child_process.cpp`.
[x] TestSupport Windows environment backend uses `platform/win32/win32_environment.cpp`.
[x] TestSupport core delegates OS behavior through `tools/test_support/internal/test_support_platform.h`.
[x] TestSupport does not depend on Logger or Assert.
[x] TestSupport local CMake options use the `TEST_SUPPORT_...` prefix when options become necessary.
[x] TestSupport exported compile definitions use the `GAMEWIP_TEST_SUPPORT_...` prefix when exported macros become necessary.
[x] `Types::ReportOptions` controls console output, report-file output, append behavior, and report path.
[x] Report output creates parent directories as needed.
[x] Report output supports `[INFO]`, `[PASS]`, `[FAIL]`, `[SKIP]`, `[MANUAL]`, `[METRIC]`, `[STRESS]`, `[SUMMARY]`, and `[RESULT]`.
[x] `Types::Summary` tracks passed, failed, and skipped counts with `total()` and `ok()`.
[x] `Types::SuiteResult` stores suite name, summary, elapsed milliseconds, and `ok()`.
[x] `Context` records info/manual/metric/stress/summary/pass/fail/skip entries.
[x] `Context` expectations record failures and keep the runner alive.
[x] `Context` expectations include `expectTrue`, `expectFalse`, `expectEq`, `expectNe`, `expectNear`, `expectContains`, `expectFileContains`, and `expectFileOccurrenceCount`.
[x] Failure reporting includes `std::source_location`.
[x] `Runner` owns one unified run report and runs named suites.
[x] `Runner` exposes aggregate result state and process exit code.
[x] `Section` provides RAII section grouping and optional elapsed-time reporting.
[x] `Timer` and `Types::IterationMetric` report elapsed time and nanoseconds per iteration.
[x] File helpers cover text read/write, existence checks, substring checks, occurrence counts, directory creation, and best-effort removal.
[x] Scoped environment helpers restore prior state on destruction.
[x] Windows environment helpers update both CRT environment and process environment.
[x] Child process support covers arguments, environment overrides/unsets, timeout, output capture, and parent-environment inheritance.
[x] Child process results expose exit code, timeout state, test-requested termination state, captured output, and success/failure helpers.
[x] Manual check support provides `Types::ManualAnswer` and `promptManualCheck()`.
[x] Concurrency helpers provide `StartGate`, `StopFlag`, and `runWorkers()`.

Windows Unicode backend standard
--------------------------------
[x] Windows platform backends use explicit `W` Win32 APIs instead of ANSI APIs or generic A/W macros.
[x] Public C++ APIs keep portable UTF-8 `std::string` text and `std::filesystem::path` paths.
[x] Win32 backend code converts to UTF-16 at the platform boundary.
[x] TestSupport child-process and environment helpers use Unicode environment/process APIs.
[x] Logger and Assert Windows popup/debug-output backends use explicit Unicode APIs.

Build and tooling
-----------------
[x] CMake builds the game/test executable and library targets.
[x] Runtime test selection is controlled by TestRunOptions, not CMake.
[x] Common Controls v6 manifest resource is propagated through the Assert target in build-tree and installed-package use.
[x] `GAMEWIP_ENABLE_COVERAGE` instruments supported compilers for coverage runs.
[x] `GAMEWIP_ENABLE_LOGGER_TEST_HOOKS` and `GAMEWIP_ENABLE_ASSERT_TEST_HOOKS` enable hook APIs for test builds.
[x] Generated Doxygen configuration exists for professional HTML API docs.
[x] Top-level CMake adds `tools/test_support` after the C++ library is implemented.
[x] The game/test executable links `GameWIP::TestSupport`, `GameWIP::Logger`, and `GameWIP::Assert` after TestSupport exists.
[ ] Logger and Assert tests are migrated to use generic TestSupport helpers after the library is validated.
[x] TestSupport package config polish exists for `find_package(GameWIP_TestSupport CONFIG REQUIRED)`.
