Testing checklist
=================

Purpose
-------
This file defines what must be proven by tests. It intentionally focuses on observable contracts and failure coverage, not implementation history.

Logger API checklist
--------------------
[x] `defaultConfig`, `lowMemoryConfig`, and `throughputConfig` expose the intended defaults.
[x] `init`, double init, shutdown, double shutdown, and repeated init/shutdown behave safely.
[x] Output modes None, Console, File, and Both are covered where the platform supports them.
[x] String source, registered SourceId source, enum source, and unknown SourceId source paths are covered.
[x] Compile-time format and runtimeFormat overloads are covered.
[x] Invalid runtime formats increment `formatFailures` and do not emit bogus log lines.
[x] Long messages are truncated and counted.

Logger report checklist
-----------------------
[x] `Logger::report(...)` writes synchronously and does not increment queued stats.
[x] Reports bypass minimum level filters.
[x] Reports bypass source and level runtime filters.
[x] Reports survive a full async queue.
[x] Report timeout overloads write first, then return the bounded drain result.
[x] `reportError`, `reportFatal`, and `fatalTerminate` route through the report contract.
[x] Logger-owned fatal popup is manually validated when `enableLoggerPopupTest` is true.

Logger stats/counter checklist
------------------------------
[x] `queued` counts accepted async entries only.
[x] `written` counts entries accepted by at least one sink.
[x] `queueDropsSoft` and `queueDropsHard` count queue pressure only.
[x] Filtered logs are intentional skips and do not count as drops.
[x] `allocationFailures`, `formatFailures`, `fileWriteFailures`, `unknownSourceUses`, and `truncated` each have direct trigger tests or hook-forced tests.
[x] `resetStats` clears resettable counters while preserving lifetime queue drops.

Logger lifecycle/concurrency checklist
--------------------------------------
[x] Many producer threads can log concurrently without crash or deadlock.
[x] `flush(timeout)` while producers are active may time out but must not deadlock.
[x] Final flush after producers stop succeeds.
[x] `shutdown` while producers are active is safe.
[x] `report` while producers are active remains synchronous and safe.

Assert macro checklist
----------------------
[x] ASSERT evaluates only when assertions are enabled and aborts on failure.
[x] VERIFY always evaluates and only reports/aborts when assertions are enabled.
[x] CHECK evaluates only when checks are enabled and continues after reporting.
[x] CHECK_ONCE reports only the first failure attempt per call site.
[x] ENSURE evaluates exactly once and returns the boolean result.
[x] UNREACHABLE and DEBUG_BREAK child paths exit abnormally as expected.
[x] Diagnostics include condition, message, file, line, and caller function when enabled.
[x] Message expressions are not evaluated when diagnostics are disabled or the macro is compiled out.

Assert interactive-action checklist
-----------------------------------
[x] Automated interactive tests use `GAMEWIP_ASSERT_TEST_ACTION` and open no real UI.
[x] Ignore Once logs and continues; the same call site can report again later.
[x] Always Ignore logs once and suppresses future failures from the same macro call site.
[x] Abort logs and exits abnormally in a child process.
[x] Break logs and exits abnormally without a debugger; with a debugger attached, it breaks and can resume.
[x] VERIFY_INTERACTIVE preserves side effects even when Always Ignore suppresses later reports.

Manual Windows UI checklist
---------------------------
[x] Assert Ignore Once button is manually validated.
[x] Assert Always Ignore button is manually validated and suppresses the second same-site dialog.
[x] Assert Break button is manually validated with a debugger attached.
[x] Assert Abort button is manually validated in a child process.
[x] Logger fatal popup is manually validated through `Logger::report(..., ReportPopup::Fatal, ...)`.
[x] Manual UI tests run at the end and only when runtime options enable them.

Failure-injection / test-hook checklist
---------------------------------------
[x] Logger forced file-open failure path is tested when hooks are enabled.
[x] Logger forced file-write failure path is tested when hooks are enabled.
[x] Logger forced file-flush failure path is tested when hooks are enabled.
[x] Logger forced fatal-popup failure path is tested when hooks are enabled.
[x] Logger forced timed-flush timeout path is tested when hooks are enabled.
[x] Assert forced TaskDialog failure exercises the MessageBox fallback path when hooks are enabled.
[x] Assert forced MessageBox failure exercises the default-action fallback when hooks are enabled.
[x] Assert debugger-attached override true/false paths are tested when hooks are enabled.
[x] Assert popup-suppression override is tested when hooks are enabled.

TestSupport library API checklist
-----------------------------
[x] `Types::ReportOptions` defaults to console output enabled, report-file output enabled, append disabled, and `logs/tests/latest_test_report.txt`.
[x] `Types::Summary::total()` returns passed + failed + skipped.
[x] `Types::Summary::ok()` returns true only when failed is zero.
[x] `Types::SuiteResult::ok()` returns the suite summary status.
[x] `Context` exposes the suite name unchanged.
[x] `Context::result()` returns the current summary counts.
[x] `Context::ok()` mirrors the current summary status.
[x] `pass`, `fail`, and `skip` update only their intended counters.
[x] `info`, `manual`, `metric`, `stress`, and `summary` write categorized report lines without changing pass/fail/skip counts.
[x] `expectTrue` passes only for true values and fails with source location for false values.
[x] `expectFalse` passes only for false values and fails with source location for true values.
[x] `expectEq` and `expectNe` handle comparable values and report readable expected/actual information.
[x] `expectNear` handles exact matches, values inside tolerance, values outside tolerance, and invalid negative tolerance.
[x] `expectContains` covers present substring, missing substring, and empty substring behavior.
[x] File expectation helpers report missing/unreadable files as failures without crashing the runner.
[x] Expectations record failures and keep later checks running.
[x] TestSupport expectations do not call GameWIP Assert macros internally.

TestSupport report/runner checklist
-------------------------------
[x] Report output can be disabled for console only, file only, both, and neither.
[x] Report file parent directories are created as needed.
[x] Report append mode preserves existing content and non-append mode starts a fresh report.
[x] Report lines use the intended categories: `[INFO]`, `[PASS]`, `[FAIL]`, `[SKIP]`, `[MANUAL]`, `[METRIC]`, `[STRESS]`, `[SUMMARY]`, and `[RESULT]`.
[x] Failure lines include file, line, function, and check name.
[x] `Runner::runSuite` records suite elapsed time.
[x] `Runner` accumulates multiple suite summaries correctly.
[x] `Runner::exitCode()` returns success only when the aggregate summary is OK.
[x] A throwing suite function is recorded as a failed suite and does not prevent later suites from running if that behavior is implemented.
[x] `Section` reports start/end or duration consistently without corrupting summary counts.

TestSupport file/environment checklist
----------------------------------
[x] `readTextFile` returns file contents exactly for normal text files.
[x] `writeTextFile` creates parent directories and writes the requested text.
[x] `fileExists` returns false instead of throwing for missing paths.
[x] `fileContains` returns true only when the text occurs in the file.
[x] `countFileOccurrences` handles zero, one, multiple, and overlapping occurrence decisions explicitly.
[x] `createDirectories` succeeds for existing directories.
[x] `removeIfExists` handles missing files without failure.
[x] `ScopedEnvironmentVariable` sets a variable, restores a previous value, and unsets a previously missing value on destruction.
[x] `ScopedUnsetEnvironmentVariable` unsets a variable and restores the previous value on destruction.
[x] Windows scoped environment helpers update both `std::getenv()` visibility and child-process environment visibility.

TestSupport child-process checklist
-------------------------------
[x] `runChildProcess` starts the requested executable with arguments.
[x] Captured stdout/stderr output is available when capture is enabled.
[x] Output capture can be disabled when requested.
[x] Parent environment inheritance can be enabled and disabled.
[x] Environment entries can set variables for the child.
[x] Environment entries can unset variables for the child.
[x] Timeout terminates or otherwise stops waiting for a hung child and marks `timedOut`.
[x] Test-requested termination marks `wasTerminatedByTest`.
[x] Nonzero exit codes are reported without pretending to classify portable crash reasons.
[x] `Types::ChildProcessResult::exitedSuccessfully()` and `exitedWithFailure()` cover zero, nonzero, timeout, and terminated-by-test cases.

TestSupport manual/metrics/stress checklist
---------------------------------------
[x] `promptManualCheck` accepts yes, no, and skipped answers.
[x] Manual checks run only when runtime options explicitly enable manual UI tests.
[x] Manual checks are reported with `[MANUAL]`.
[x] `Timer` reports increasing elapsed time and resets correctly.
[x] `Timer::nanosecondsPerIteration` and `Types::IterationMetric::nanosecondsPerIteration` handle zero iterations explicitly.
[x] Metrics are reported without failing tests based on hard thresholds.
[x] `StartGate` blocks workers until opened and releases all waiters.
[x] `StopFlag` is safe for cross-thread stop requests.
[x] `runWorkers` starts the requested worker count and joins all workers before returning.
[x] Stress helper failures are reportable without deadlocking the test run.

Windows Unicode validation checklist
------------------------------------
[x] Win32 backend code avoids ANSI APIs such as `CreateProcessA`, `MessageBoxA`, `GetEnvironmentStringsA`, and `OutputDebugStringA`.
[x] Win32 backend code avoids generic macro-mapped APIs such as `CreateProcess`, `MessageBox`, `GetEnvironmentStrings`, and `OutputDebugString`.
[x] TestSupport child-process tests cover Unicode-safe command-line/environment behavior at the public API level.
[x] Scoped environment tests verify values are visible through `std::getenv()` and child-process inheritance.
[x] Captured child output remains byte-oriented `std::string`, as documented.

Performance and coverage checklist
----------------------------------
[x] Hot passing macro paths have metrics: ASSERT, CHECK, VERIFY, ENSURE, ASSERT_INTERACTIVE, VERIFY_INTERACTIVE.
[x] Logger disabled/filtered/normal enabled paths have producer-side metrics.
[x] Performance tests are metrics-only until baselines/warnings are intentionally added.
[x] Coverage builds can identify unexecuted logger/assert lines, functions, and branches.
[x] The optional `coverage` target exists when coverage is enabled.
[x] If gcovr is available, the `coverage` target generates an HTML report and XML report.
[x] If gcovr is missing, the `coverage` target fails with a clear installation message instead of disappearing silently.
[x] Coverage reports are reviewed after hook-forced tests are added.

Documentation validation checklist
----------------------------------
[x] `GAMEWIP_BUILD_DOCS=ON` creates the `docs` target when Doxygen is installed.
[x] Missing Doxygen produces a clear configure-time error only when documentation is explicitly enabled.
[x] Root docs link to Logger, Assert, and TestSupport guide pages.
[x] Logger guide pages cover quick start, configuration, reports, stats, testing, and examples.
[x] Assert guide pages cover quick start, macros, interactive assertions, testing, and examples.
[x] Header comments remain contract-focused; tutorial-style material lives in Markdown guide pages.
[x] TestSupport guide pages cover quick start, expectations, reports, child processes, scoped environment variables, manual checks, metrics, stress helpers, and examples.
[x] TestSupport Doxygen registration adds the TestSupport public header and `tools/test_support/docs/` without editing the root Doxyfile input list.
[x] Root docs link to the TestSupport landing page after TestSupport is registered with Doxygen.

Doxygen/build-tool validation addendum
--------------------------------------
[x] `cmake --build build-docs --target docs --verbose` prints the generated HTML path and warning-log path.
[x] The Doxygen warning log is checked after docs generation.
[x] The Doxygen sidebar groups library pages under Logger and Assert instead of flattening every guide page at the root.
[x] `GAMEWIP_INSTALL_DOCS=ON` installs generated HTML docs only when `GAMEWIP_BUILD_DOCS=ON`.
[x] Coverage generation tolerates known gcov negative-hit warnings and still writes HTML/XML reports.
